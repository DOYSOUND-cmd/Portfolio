概要

　PYNQ-Z2のFPGA上に信号処理回路を構築し、ギター入力に対してリアルタイムに信号処理を行うギター用マルチエフェクターです。ノイズサプレッサー、コンプレッサー、ワウ、オーバードライブ、ディストーション、アンプシミュレーター、キャビネットシミュレーター、EQ、コーラス、リバーブの10ブロックを1つの信号処理チェーンとして実装しています。アンプ6機種、オーバードライブ6機種、ディストーション系ペダル7種類、コーラス3機種など、多くのエフェクトで実在の機材をモデルにした機種切替に対応しています。

　ギター信号は、Pmod I2S2オーディオモジュールのADC（CS5343）で96 kHz / 24-bitにデジタル化します。これをPL側（FPGA回路部分）のDSPパイプラインで処理し、同モジュールのDAC（CS4344）から出力します。エフェクトのON/OFFやパラメータ変更はPS側（CPU・Linuxが動作する部分）のPythonから制御し、信号処理はFPGA側の専用回路でリアルタイムに実行する構成にしました。操作系として、HDMI接続の5インチLCDに表示するGUIのほか、ロータリーエンコーダ、フットスイッチ、エクスプレッションペダルを自作のFPGA回路として統合しています。

完成イメージ

ギターエフェクターとは

　ギターエフェクターとは、エレキギターの音色や音量、周波数バランス、空間感を変化させるための機器です。音を歪ませる、ノイズを抑える、音の粒をそろえる、残響を加えるなどの処理によって、演奏者が求めるサウンドを作ります。

　このプロダクトでは、複数のエフェクトを1つの信号処理チェーンとして接続し、FPGA上でリアルタイムに処理するマルチエフェクターとして設計しています。

FPGA / PYNQ とは

　FPGAは、内部の論理回路や配線構成を目的に応じて書き換えられる半導体デバイスです。CPUが命令を順番に実行するのに対し、FPGAでは処理内容を専用のハードウェア回路として構成できます。そのため、一定周期でデータを処理し続ける音声信号処理や、低レイテンシが求められるリアルタイム処理に向いています。

　PYNQは、Zynq SoCのFPGA領域をPythonから扱いやすくするための開発環境です。本プロジェクトでは、PS側でGUIやパラメータ制御を行い、PL側で音声信号処理を実行する構成を採用しています。

システム構成

　入力されたギター信号は、Pmod I2S2オーディオモジュールに搭載されたCS5343 ADCによって96 kHz / 24-bitのデジタル信号に変換されます。デジタル化された音声データはI2S形式で受け取られ、AXI-Stream形式に変換された後、FPGA側のDSPパイプラインへ送られます。

　FPGA内部では、これら10ブロックを順番に処理します。処理後の信号は再びI2S形式に戻され、CS4344 DACを通してアナログ信号として出力されます。全エフェクトOFF時には、入力と出力がビット単位で一致する完全なバイパスになるよう設計しています。

　深い歪み処理の論理は100 MHzのファブリッククロックではタイミング収束せず、最悪スラック（WNS）が約-10 nsまで悪化していました。そこでDSPコアだけを33.33 MHzの専用クロックアイランドに隔離し、クロック間はAXI-Streamのクロックコンバータで接続する構成に変更しています。これで96 kHzの1サンプルあたり約347サイクルの余裕が生まれます。そのうえで各エフェクトを1段1機能の小さなレジスタステージの連鎖としてパイプライン化し、現行ビルドはWNS +0.457 nsでタイミング収束しています。

　エフェクトのON/OFFやパラメータ変更は、ZynqのPS側で動作するLinux/Pythonから制御します。音声処理はPL側のFPGA回路、設定変更やGUI操作はPS側のPythonに分担させることで、リアルタイム処理と操作性を両立させています。

　制御レジスタはエフェクトブロックごとに独立したAXI GPIOとして実装しており、PS側は32-bitの制御ワードを書き込むだけで、音声データの経路には一切介在しません。パラメータはGUI上0〜100の統一スケールに揃えています。クロックアイランドをまたぐ制御ワードは2段フリップフロップと安定検出で同期してからDSPに反映するため、演奏中に動かしてもノイズが乗りにくい構成です。

開発の流れ

　まず、各エフェクトの信号処理アルゴリズムを設計し、固定小数点演算で実装できる形に整理しました。その後、Clashを用いてFPGA上に実装するDSP回路を記述し、生成したVHDLをVivadoへ取り込みました。

　Vivado上では、PYNQ-Z2の既存オーディオ入出力系にDSPパイプラインを接続し、合成・配置配線を行ってbitstreamとhwhファイルを生成します。生成した回路データをPYNQ-Z2へ配置し、PS側のPythonからOverlayとして読み込むことで、実機上で信号処理とパラメータ制御を確認しました。

　Clashでの記述は固定小数点演算を前提にしており、音量調整やクリッピング処理ではビット幅と飽和処理を意識してオーバーフローによるノイズが発生しにくいよう設計しています。実機評価では入力から出力まで各段で実際に音を聴きながら、ノイズ・音量差・パラメータ応答を確認しました。

　また、音作りの反復を高速化するため、FPGAと同一のClash回路記述をホストPC上でそのまま実行するオフラインDSPシミュレーション環境を整備しました。周波数特性や歪みのキャラクター、機種別モデルの音の差をVivadoでの合成前に自動チェックし、全エフェクトOFF時のビット完全バイパスを不変条件として回帰テストで保証しています。そのうえで、最終的な合否は必ず実機での試聴によって判定する開発サイクルにしています。

　制御ソフト側にも自動テストを整備しています。レジスタへの書き込み内容やプリセット、GUIの状態管理、エンコーダ入力のデコードなどを対象に、約170件のPython単体テストを実機なしで実行できるようにしました。実機上では、オーディオ経路・エンコーダ・HDMI出力それぞれのスモークテストスクリプトで確認します。ビルドはmake一発でbitstreamとhwhが生成され、デプロイスクリプトがボード上の参照箇所へ同期してハッシュ値で整合を検証する、再現可能な手順にまとめました。

bitstream：FPGA に書き込む回路データ。 hwh：Python 側が回路構成やアドレス情報を理解するための情報ファイル。 Overlay：PYNQ で Python から読み込む FPGA 回路データ一式。

GUI サンプル

操作系（エンコーダ / フットスイッチ / ペダル）

　ロータリーエンコーダは市販のUSBコントローラではなく、PL側の自作IPとして実装しています。接点入力を2段フリップフロップで同期したうえでデバウンスし、A/B相のクアドラチャ信号をデコードして符号付きの回転量として蓄積、PS側のPythonはそれをポーリングで読み出すだけの構成です。3つのフットスイッチも同様に専用IPで受けています。

　操作の流れは「GUIファースト」の一方向データフローに統一しました。エンコーダやフットスイッチの入力はまずGUI側の状態を更新し、その状態だけを実機のレジスタへ反映します（連続回転時は20 ms間隔に間引いて適用）。どの入力手段から操作しても、画面表示と実機の設定が食い違わないようにするための設計です。

Noise Suppressor

　入力信号のエンベロープ、つまり振幅の包絡線をサンプルごとに追跡し、設定した閾値と比較して出力ゲインを制御します。信号レベルが閾値を下回ると、ゲインを徐々に下げることで、弦を弾いていないときの環境ノイズやハムノイズを抑制します。 DECAYパラメータでゲインが下がる速さを、DAMPパラメータで最大抑制量を調整できます。完全にミュートする設定から、自然に音量を下げる設定まで調整できるようにしています。 単純なオン／オフ式のゲートではなく、平滑化されたゲイン制御として実装することで、音の切れ際が不自然になりにくい構成を目指しました。 NS-2 / The Silencer / Smart Gateの3機種のモデル切替に対応し、ゲートの閉じる深さや床の柔らかさといったキャラクターの違いを係数のみで作り分けています。

Compressor

　入力信号のエンベロープをサンプルごとに追跡し、設定した閾値を超えた信号に対してゲインリダクションを行います。閾値を超えた分をRATIOパラメータに応じて圧縮することで、大きな音を抑え、音量差を整えます。 RESPONSEパラメータでは圧縮が戻る速さを制御します。実機のコンパクトコンプレッサーに合わせてアタックとリリースを非対称の時定数とし、アタックは機種ごとに約2.7〜5.3 ms、リリースはRESPONSEに応じて約80 ms〜1.4 sの範囲で変化します。これにより、ピッキングのアタック感を残しながら音量のばらつきを抑えたり、サステインを整えたりする調整が可能になります。 Dyna Comp / Ross / CS-3の3機種のモデル切替に対応し、深く潰れるスカッシュ感、ゆっくり戻るブルーム感、パンチのある現代的な音、と性格を変えています。

Wah

　ステート・バリアブル・フィルタ（SVF）によるレゾナントバンドパスフィルタで、通過帯域を上下にスイープさせて「ワウ」という音色変化を作ります。スイープ範囲は定番ワウペダルのCry Baby GCB-95を参考に約450 Hz〜2.2 kHzに調整し、Qパラメータでレゾナンスの強さを制御します。 ペダル位置はGUIやエンコーダからの操作に加えて、エクスプレッションペダル（ZOOM FP02M）をFPGA内蔵のADC（XADC）で読み取ることで足元からリアルタイムに操作できます。配置は歪みの前段で、クラシックなワウペダルと同じ構成です。

Overdrive

　入力信号をDRIVEパラメータで増幅し、ソフトクリッピング処理を通すことで、波形の山と谷を緩やかに丸めます。ハードクリッピングのように急激に波形を切り落とすのではなく、入力レベルが大きくなるほど滑らかに圧縮されるため、比較的自然で扱いやすい歪みになります。 強く弾いたときには歪みが増え、弱く弾いたときには原音のニュアンスが残りやすいため、ピッキングの強弱に反応する歪みを狙っています。 TS9 / OD-1 / BD-2 / Jan Ray / OCD / Centaurの6機種のモデル切替に対応し、クリップの硬さ・非対称性やクリップ前の周波数特性を機種ごとの係数で作り分けています。和音を弾いたときに濁りの原因となる偶数次の混変調歪みを抑えるため、クリップ特性は対称型を基本に調整しました。

Distortion

　入力信号を大きく増幅したうえでハードクリッピングを適用し、波形の山と谷を一定レベルで切り落とします。これにより波形は矩形波に近づき、倍音成分が増加します。 ソフトクリッピングを用いるオーバードライブに比べて波形の変化が急峻なため、より強く、輪郭の立った歪みになります。アタックを強く弾いたときにはクリッピング量が増え、ザラつきのある飽和感が得られるように設計しています。 ディストーション系は、Clean Boost / Tube Screamer / RAT / DS-1 / Big Muff / Fuzz Face / Metalの7種類をそれぞれ独立したFPGA回路の段として実装しています。単一の切替式ではなくマスク方式なので、複数のペダルを同時にONにできます。ハードクリッピング系のペダルでは4倍オーバーサンプリングとデシメーションFIRフィルタを組み合わせ、折り返し歪み（エイリアスノイズ）を抑制しています。

Amp Simulator / Cab IR

　アンプシミュレーターとキャビネットIRは、ギターアンプとスピーカーキャビネットを通したときの音色変化を再現するための処理です。

　アンプシミュレーターは、HPF → 増幅 → 波形整形 → 第2ステージ → トーンスタック → パワー段 → マスターという多段カスケードで構成しています。GAINで信号を増幅し、BASS / MIDDLE / TREBLE / PRESENCE の各トーンフィルタで周波数特性を調整します。RESONANCEでは低域の共鳴感を付加し、MASTERで最終的な出力レベルを制御します。DRVモードで、クリーン／ドライブの2チャンネルを切り替えられます。JC-120 / Twin Reverb / AC30 / Rockerverb / JCM800 / TriAmpの6機種は、係数のみで作り分けています。パワー管の電源電圧降下（サグ）による音の沈み込みも、エンベロープ追従でモデル化しました。

　続くCab IRでは、スピーカーキャビネットの周波数特性を47タップの対称FIRフィルタとレゾナンス用フィルタの組み合わせで近似し、信号に畳み込みます。ライン出力のフラットな信号に対して、キャビネット特有の高域減衰や中域のまとまり、コーン紙の共振によるプレゼンス帯域のピークを加えることで、直接出力の硬さを抑え、アンプを通した音に近い質感を狙っています。キャビネットは1x12オープンバック / 2x12ブリティッシュ / 4x12クローズドの3種類から選択できます。

EQ

　LOW / MID / HIGH の3バンドで全体の音色バランスを整えるイコライザーです。帯域分割は一次フィルタの出力の差分だけで構成しており、分割処理そのものには乗算器を使わないFPGA向けの軽量な実装になっています。3バンドすべてが中立設定のときは入力信号がビット単位でそのまま通過し、大きくブーストしたときも急激に歪まないようソフトに飽和させる設計です。

Chorus

　原音にわずかに遅らせた音を重ね、その遅延時間をLFOで周期的に揺らすことで、音に広がりと揺らぎを加えるエフェクトです。FPGA内蔵のBRAMを、2048サンプル×2本の可変ディレイライン（最大約21 ms）として使っています。書き込み位置から「現在の遅延量」だけ遡った位置を読み出すことで、アナログBBDコーラス本来のピッチ揺れを再現しました。遅延量は16-bit分解能の三角波LFOで滑らかに動かし、読み出しは隣接2サンプルの線形補間で行うことで、遅延の階段状の変化によるジッパーノイズを抑えました。

　RATE / DEPTH / MIX のパラメータに加えて、CE-2 / Small Clone / Dimension Dの3機種のモデル切替に対応しています。遅延の中心値・揺れ幅・LFOの速さや波形・ウェット信号の高域特性を機種ごとに変えることで、CE-2の暗めで揺れの分かりやすい音から、Dimension Dのさりげなく明るい広がりまでを作り分けています。配置はEQの後段、リバーブの前段です。

Reverb

　フィードバックループを持つBRAMディレイラインを組み合わせたアルゴリズムで残響を生成します。入力信号をループ内で繰り返し反射させながら徐々に減衰させることで、空間の響きを模擬します。単一のディレイラインでは残響の尾が金属的な響きになりやすいため、フィードバック経路にオールパスフィルタによる拡散処理を加え、ディレイ長を伸ばさずに反射の密度を高めています。DECAYで残響の長さ（減衰速度）を、TONEで残響成分の高域フィルタ特性を制御します。MIXで原音と残響の混合比を調整します。 M300 / Keeley Omni / Hall of Fame / RV-6の4機種のモデル切替に対応し、暗めでドライな響きから明るくウェットな響きまでを作り分けています。音に少し距離感と奥行きが生まれ、ドライな音がまとまりのある空間の中に置かれているように聴こえます。

チェーンプリセット

　複数エフェクトのON/OFFとパラメータをまとめて切り替えるチェーンプリセットを13種類用意しています。プリセットはPS側のPythonが各エフェクトの設定を一括で書き込む形で実装しており、GUIからの選択のほか、フットスイッチでの順送り・逆送りにも対応します。全エフェクトOFFの「Safe Bypass」も用意しており、どんな状態からでもワンアクションで素の音に戻せます。

音響評価・信号解析

レイテンシー計測

　FPGA上のDSPパイプラインがギター演奏に与える遅延を確認するため、入力信号、バイパス出力、全7エフェクト有効時の出力を比較しました。入力信号とバイパス出力の比較からシステム経路の参考遅延を、エフェクトなし基準信号と全7エフェクト有効時の出力の比較から全エフェクト有効時の相対遅延を測定しています。

　遅延推定にはGCC-PHATと波形相互相関を併用しました。GCC-PHATは音量差や周波数特性差の影響を比較的受けにくいため、窓中央値を主な採用値としています。グラフ上段では、横軸が遅延サンプル数、鋭いピークの位置が推定遅延量です。

　中段の波形相互相関は、2つの波形が最も似ている位置を確認する補助指標です。ギター信号は周期性を持つため、別のピークを拾う場合があります。下段は推定遅延に基づいて波形を重ねた図で、波形の完全一致ではなく、アタックのタイミングを確認しています。

　測定結果として、入力信号からバイパス出力までの参考遅延は約51.6 samples、48 kHz換算で約1.08 msでした。全7エフェクト有効時の遅延は約53.1 samples、約1.11 msで、今回の測定条件では7種類のエフェクトを直列に通しても大きな遅延増加は確認されませんでした。 この結果から、複数のDSPブロックをFPGA上に直列実装しても、十分に低い遅延を維持できることを確認しました。

　各メーカーのマルチエフェクターの実測例と比べても、本機の約1.11 msは1 ms台前半の低遅延レンジに入ります。

入力とバイパスの比較

　入力信号とバイパス出力の正規化スペクトルを比較しました。横軸は対数スケールの周波数、縦軸は最大レベルを0 dBにそろえた正規化PSDです。音量差ではなく、どの周波数帯が相対的に強いかを確認できます。青線が入力信号、橙線がバイパス出力です。

　本システムのバイパスは、機械式の完全バイパスではありません。入力信号はアナログ入力段、ADAU1761 codec、I2S、FPGA、DAC、録音経路を通過するため、バイパス出力にはハードウェア経路や録音環境の特性も含まれます。

　グラフでは、入力信号は1〜3 kHz付近の中高域成分が強く、ギターの輪郭やピッキング感に関わる帯域が確認できます。一方、バイパス出力は低域寄りに見え、1 kHz以上の成分が弱くなっています。

エフェクトごとの周波数特性と時間変化

　各エフェクト出力について、帯域別エネルギー比率、正規化スペクトル、スペクトログラムを用いて解析しました。ここでは音量の大小ではなく、各エフェクトの音色傾向、歪みによる倍音、高域ノイズやfizz、周波数成分の時間変化を確認しています。

帯域別エネルギー比率のヒートマップ

　帯域別エネルギー比率のヒートマップは、各音源のエネルギーがどの周波数帯に集中しているかを比較するグラフです。行が各音源、列が周波数帯域を表し、各セルの数値は該当帯域が占める割合です。明るいセルほど、その帯域にエネルギーが集中しています。

　20〜80 Hzは超低域や振動成分、80〜250 Hzは音の太さ、250 Hz〜1 kHzはギターの芯、1〜3 kHzはピッキング感や抜け、3〜8 kHzはアタック感やfizz、8〜16 kHzは超高域成分やデジタル的なざらつきに関係します。

　入力信号では250 Hz〜1 kHzおよび1〜3 kHzの割合が大きく、ギターの芯や輪郭に関わる中域〜中高域成分が多いことが分かります。一方、バイパス出力は80〜250 Hzが大きく、低域寄りの傾向を示しています。この差にはハードウェア要因も含まれるため、DSPエフェクト単体の評価とは切り分けています。

　DS-1 Distortionでは250 Hz〜1 kHz付近の中域が増え、ディストーションらしい押し出しが確認できます。Amp Simでは8〜16 kHz帯域が16.1%と大きく、超高域成分が強く出ています。fizzやデジタル臭さにつながる可能性があるため、後段のCab SimやLPFによる高域減衰処理が改善対象です。

正規化スペクトル比較

　正規化スペクトル比較では、各信号の最大スペクトルレベルを0 dBにそろえ、音量差の影響を除いた状態でスペクトル形状を比較しています。横軸は周波数、縦軸は相対的な強さで、線が高い帯域ほど目立つ成分が多いことを表します。

　正規化スペクトルでは、バイパス、ノイズサプレッサー、コンプレッサー、キャビネットシミュレーター、リバーブが低域〜中低域寄りに見えます。入力からバイパスまでの基準経路自体も低域寄りに見えるため、ハードウェア経路の影響も含めて評価する必要があります。

　DS-1 Distortionは中域の成分が目立ち、歪みエフェクトとしてのキャラクターがスペクトル上にも現れています。一方、Amp Simは8 kHz以上の成分が強く、後段で適切に整えないと耳に痛い高域やfizzとして聞こえる可能性があります。

　全7エフェクト有効時は1〜3 kHzの中高域成分が保持され、ギターの輪郭に関わる帯域が残っています。一方で3〜8 kHz帯域も残るため、抜けを残しながら高域のざらつきを抑える調整が必要です。今後はAmp Sim後段の高域減衰処理とCab Simの周波数特性を調整します。

スペクトログラム

　スペクトログラムは、周波数成分の時間変化を可視化したものです。横軸が時間、縦軸が周波数、色の強さが成分の強さを示します。演奏中のどのタイミングでどの帯域が強く出ているかを確認できます。

　縦方向に明るい筋はピッキングの瞬間、音の後ろに残る色はサステインやリバーブ成分、高域に広く出続ける色は高域ノイズやfizzの候補として読み取れます。

　ノイズサプレッサーは、演奏していない区間で不要な成分を抑えるように動作しており、バイパスに近い時間周波数分布を保ちながら、非演奏時に高域成分が大きく残りにくい傾向が確認できます。今後は無音入力やノイズを含む信号を用いて、ゲートの開閉や減衰挙動をより詳細に評価していきます。

　Amp Simでは高域側に広く成分が見られます。8 kHz以上が強く残ると、耳に痛いfizzやデジタル的なざらつきとして聞こえる可能性があります。Cab Simでは高域を抑える方向の特性が見られるため、今後は5〜6 kHz以上の減衰量や2〜4 kHzの抜けを調整します。

全体を通して

　今回の解析では、全7エフェクト有効時でも1〜3 kHz帯域が45.5%となり、ギターの輪郭に関わる中高域成分が保持されていました。一方で、Amp Simでは8〜16 kHz帯域が大きく、全7エフェクト有効時にも3〜8 kHz帯域が残るため、高域の抜けを残しながらfizz成分を抑える調整が必要です。

　現時点のDSPパイプラインは、低遅延で複数エフェクトを直列処理できています。一方、音質面ではAmp Sim後段の高域制御とCab Simの周波数特性が主要な改善ポイントだと考えています。

開発状況と今後の予定

　現在も開発を継続中です。ビルドは「候補ビルドを実機で試聴し、問題がなければ採用版に昇格させる」2段階で運用しており、bitstreamとhwhの世代はハッシュ値で管理しています。現行の候補ビルドはコーラスを追加した世代で、前述のとおりタイミングは収束済みです。

　今後は、音響解析の結果を踏まえて、アンプシミュレーター後段の高域制御とキャビネットシミュレーターの周波数特性を調整します。あわせて、無音・ノイズ入力を使ったノイズサプレッサーの詳細評価と、各機種モデルのキャラクターの追い込みを進める予定です。
